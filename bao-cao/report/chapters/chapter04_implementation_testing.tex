\chapter{Xây dựng, triển khai và kiểm thử hệ thống}

\section{Cài đặt hệ thống}

\subsection{Môi trường phát triển}

Dự án SmartNutri được phát triển trên môi trường Windows với các công cụ chính sau:

\begin{itemize}
    \item \textbf{IDE:} Visual Studio Code và Android Studio — dùng để viết code Flutter/Dart, React/TypeScript và quản lý Android Emulator.
    \item \textbf{Flutter SDK:} Phiên bản 3.x, ngôn ngữ Dart — phát triển ứng dụng di động.
    \item \textbf{Node.js:} Phiên bản 20 LTS — môi trường runtime cho Cloud Functions và Admin Web.
    \item \textbf{Firebase CLI:} Công cụ dòng lệnh để khởi tạo project, deploy Cloud Functions, Firestore Rules, Storage Rules và Hosting.
    \item \textbf{Git \& GitHub:} Quản lý mã nguồn và phiên bản.
    \item \textbf{Android Emulator / Thiết bị Android thật:} Môi trường chạy và kiểm thử ứng dụng trong quá trình phát triển.
\end{itemize}

\subsection{Cài đặt ứng dụng di động (Flutter)}

Ứng dụng di động SmartNutri được phát triển bằng Flutter. Các bước thiết lập môi trường và chạy ứng dụng:

\begin{enumerate}
    \item Cài đặt Flutter SDK và cấu hình biến môi trường.
    \item Tạo project Flutter mới hoặc clone mã nguồn từ GitHub:
    \begin{verbatim}
    git clone <repository-url>
    cd SmartNutri
    flutter pub get
    \end{verbatim}
    \item Cấu hình Firebase cho Flutter:
    \begin{itemize}
        \item Tải file \texttt{google-services.json} từ Firebase Console (dành cho Android).
        \item Đặt file này vào thư mục \texttt{android/app/}.
        \item File \texttt{GoogleService-Info.plist} cho iOS được chuẩn bị tương tự nếu hỗ trợ iOS trong tương lai.
    \end{itemize}
    \item Chạy ứng dụng trên thiết bị hoặc máy ảo:
    \begin{verbatim}
    flutter run
    \end{verbatim}
    \item Build file APK để cài đặt hoặc phân phối:
    \begin{verbatim}
    flutter build apk --release
    \end{verbatim}
\end{enumerate}

Ứng dụng Flutter được tổ chức theo kiến trúc \textbf{feature-first}:

\begin{itemize}
    \item \textbf{Tầng Presentation:} Chứa các widget Flutter cho từng màn hình (pages) và các component dùng chung (widgets).
    \item \textbf{Tầng Business Logic:} Sử dụng Provider/ChangeNotifier để quản lý state và xử lý logic nghiệp vụ.
    \item \textbf{Tầng Service:} Chứa các service class tương tác với Firebase (AuthService, FirestoreService, StorageService) và Gemini API.
    \item \textbf{Tầng Model:} Định nghĩa các data class tương ứng với document Firestore.
\end{itemize}

\subsection{Cài đặt Firebase backend}

Firebase được sử dụng làm nền tảng backend chính cho toàn bộ hệ thống. Các bước thiết lập:

\begin{enumerate}
    \item Tạo project trên \textbf{Firebase Console} (https://console.firebase.google.com). Project mặc định cho môi trường phát triển có tên \texttt{smartnutri-dev-2e67b}.
    \item \textbf{Firebase Authentication:} Kích hoạt các phương thức đăng nhập Email/Password và Google Sign-In trong mục Authentication > Sign-in method.
    \item \textbf{Cloud Firestore:} Tạo database Firestore ở chế độ Native mode. Cấu hình Security Rules để giới hạn quyền truy cập dữ liệu theo UID của người dùng đã xác thực.
    \item \textbf{Firebase Storage:} Kích hoạt Storage và cấu hình Security Rules cho phép người dùng đọc/ghi file trong đường dẫn \texttt{users/\{userId\}/}.
    \item Triển khai Firestore Rules, Storage Rules và Indexes lên Firebase:
    \begin{verbatim}
    firebase deploy --only firestore:rules,firestore:indexes
    firebase deploy --only storage
    \end{verbatim}
\end{enumerate}

\subsection{Cài đặt Cloud Functions}

Cloud Functions xử lý các tác vụ backend yêu cầu bảo mật hoặc logic phức tạp. Mã nguồn nằm trong thư mục \texttt{functions/}, sử dụng Node.js 20 và TypeScript.

\begin{enumerate}
    \item Cài đặt dependencies:
    \begin{verbatim}
    cd functions
    npm install
    \end{verbatim}
    \item Biên dịch TypeScript:
    \begin{verbatim}
    npm run build
    \end{verbatim}
    \item (Tùy chọn) Chạy Firebase Emulator để kiểm thử cục bộ:
    \begin{verbatim}
    firebase emulators:start --only functions,firestore,auth
    \end{verbatim}
    \item Triển khai lên Firebase:
    \begin{verbatim}
    npm run deploy
    \end{verbatim}
\end{enumerate}

Các Cloud Function chính trong hệ thống:
\begin{itemize}
    \item \texttt{identifyFoodImage} — Nhận ảnh từ client, gọi Gemini API để nhận diện món ăn, quản lý quota AI scan.
    \item \texttt{suggestMeals} — Gợi ý bữa ăn dựa trên chỉ tiêu dinh dưỡng còn lại của người dùng.
    \item \texttt{chatNutrition} — Xử lý chat với Gemini API cho chatbot tư vấn dinh dưỡng.
    \item \texttt{barcodeLookup} — Tra cứu thông tin dinh dưỡng từ mã vạch sản phẩm qua OpenFoodFacts API.
    \item \texttt{setUserSubscription} — Quản trị viên gán gói Premium cho người dùng (yêu cầu admin claim).
    \item \texttt{setAdminRole} — Quản trị viên phân quyền admin cho người dùng khác.
    \item \texttt{seedFoods} — Import hàng loạt thực phẩm vào Firestore.
\end{itemize}

\subsection{Cài đặt trang Admin Web}

Trang quản trị được phát triển bằng React 18, TypeScript và Vite. Mã nguồn nằm trong thư mục \texttt{admin-web/}.

\begin{enumerate}
    \item Cài đặt dependencies:
    \begin{verbatim}
    cd admin-web
    npm install
    \end{verbatim}
    \item Chạy môi trường phát triển:
    \begin{verbatim}
    npm run dev
    \end{verbatim}
    \item Build production:
    \begin{verbatim}
    npm run build
    \end{verbatim}
    \item Deploy lên Firebase Hosting:
    \begin{verbatim}
    firebase deploy --only hosting
    \end{verbatim}
\end{enumerate}

Trang admin cung cấp giao diện web cho quản trị viên thực hiện: quản lý danh mục thực phẩm (thêm, sửa, xóa, import CSV), xem danh sách người dùng, gán Premium và phân quyền admin.

\subsection{Cấu hình Gemini API}

Google Gemini API được sử dụng cho các tác vụ AI trong hệ thống. Cấu hình được thực hiện như sau:

\begin{enumerate}
    \item Tạo API key từ \textbf{Google AI Studio} (https://aistudio.google.com).
    \item Thiết lập biến môi trường \texttt{GEMINI\_API\_KEY} trên Cloud Functions:
    \begin{verbatim}
    firebase functions:config:set gemini.api_key="YOUR_API_KEY"
    \end{verbatim}
    Hoặc tạo file \texttt{.env} trong thư mục \texttt{functions/} cho môi trường phát triển cục bộ.
    \item Trong code Cloud Functions, API key được đọc từ biến môi trường:
    \begin{verbatim}
    const key = process.env.GEMINI_API_KEY;
    \end{verbatim}
    \item Model được sử dụng là \texttt{gemini-2.5-flash} — model nhẹ, phản hồi nhanh, phù hợp với các tác vụ nhận diện ảnh và sinh văn bản tiếng Việt.
    \item API key không được nhúng vào mã nguồn phía client (Flutter app hay Admin Web). Mọi request đến Gemini đều đi qua Cloud Functions để bảo vệ khóa.
\end{enumerate}

\subsection{Trạng thái triển khai hiện tại}

Ở giai đoạn hiện tại, hệ thống được triển khai và kiểm thử trong \textbf{môi trường phát triển} (development):

\begin{itemize}
    \item \textbf{Ứng dụng di động:} Chạy trên Android Emulator và thiết bị Android thật qua lệnh \texttt{flutter run}. File APK debug được build để kiểm thử nội bộ. Chưa triển khai lên Google Play Store.
    \item \textbf{Backend Firebase:} Sử dụng Firebase project \texttt{smartnutri-dev-2e67b} cho môi trường phát triển. Firestore, Authentication, Storage và Cloud Functions đã được cấu hình và hoạt động.
    \item \textbf{Trang quản trị:} Chạy trên môi trường local (\texttt{npm run dev}) trong quá trình phát triển. Bản build production được deploy lên Firebase Hosting để kiểm thử.
    \item \textbf{Gemini API:} API key được cấu hình trên Cloud Functions thông qua biến môi trường. Các request từ client đến Cloud Functions và từ Cloud Functions đến Gemini đều hoạt động trong môi trường phát triển.
\end{itemize}

\subsection{Quy trình triển khai}

Khi có thay đổi cần cập nhật lên môi trường phát triển, quy trình triển khai điển hình như sau:

\begin{enumerate}
    \item \textbf{Ứng dụng di động:} Sau khi thay đổi code Flutter, chạy \texttt{flutter build apk --debug} để tạo APK mới và cài đặt lên thiết bị kiểm thử.
    \item \textbf{Cloud Functions:} Biên dịch TypeScript (\texttt{npm run build}) và deploy lên Firebase (\texttt{npm run deploy} hoặc \texttt{firebase deploy --only functions}).
    \item \textbf{Trang quản trị:} Build production (\texttt{npm run build}) và deploy lên Firebase Hosting (\texttt{firebase deploy --only hosting}).
    \item \textbf{Firestore Rules \& Storage Rules:} Khi thay đổi quyền truy cập, deploy rule mới qua \texttt{firebase deploy --only firestore:rules,storage}.
\end{enumerate}

\subsubsection{Nhận xét về kết quả kiểm thử quét AI}

Từ kết quả kiểm thử trên, nhóm rút ra một số nhận xét sau:

\begin{itemize}
    \item \textbf{Điều kiện ảnh ảnh hưởng đến độ chính xác:} AI có xu hướng nhận diện chính xác hơn khi ảnh chụp rõ nét, đủ ánh sáng và món ăn được trình bày ở góc nhìn thuận lợi (từ trên xuống hoặc chính diện). Các ảnh chụp dưới ánh sáng yếu hoặc góc chụp quá nghiêng có thể cho độ tin cậy thấp hơn. Trường hợp bánh mì đạt độ tin cậy cao nhất (91\%) một phần do món ăn có hình dạng đặc trưng, dễ phân biệt. Ngược lại, gỏi cuốn có độ tin cậy thấp nhất (74\%) do lớp bánh tráng trong suốt làm khó quan sát thành phần bên trong.

    \item \textbf{Kết quả dinh dưỡng chỉ mang tính ước tính:} Gemini API trả về thông tin dinh dưỡng dựa trên phân tích hình ảnh và tri thức được huấn luyện, không phải từ phân tích hóa học thực tế. Các con số calo và chất dinh dưỡng đa lượng có thể dao động tùy theo cách chế biến, nguyên liệu cụ thể và khẩu phần thực tế. Do đó, giá trị dinh dưỡng do AI cung cấp nên được xem là con số tham khảo ban đầu, không thay thế cho việc tra cứu từ cơ sở dữ liệu dinh dưỡng chính thống.

    \item \textbf{Người dùng cần được phép chỉnh sửa trước khi lưu:} Hệ thống cho phép người dùng điều chỉnh thông tin dinh dưỡng và khối lượng phần ăn sau khi AI trả về kết quả, trước khi lưu vào nhật ký. Đây là bước quan trọng để người dùng hiệu chỉnh các sai lệch do AI ước tính và đảm bảo dữ liệu nhật ký phản ánh chính xác hơn thực tế tiêu thụ. Nhóm khuyến nghị người dùng nên kiểm tra và điều chỉnh kết quả AI, đặc biệt với các món ăn có cách chế biến phức tạp hoặc khẩu phần khác biệt so với thông thường.
\end{itemize}

Nhìn chung, Gemini API thể hiện khả năng nhận diện tốt các món ăn Việt Nam phổ biến trong điều kiện ảnh chụp thông thường. Độ chính xác của thông tin dinh dưỡng ở mức chấp nhận được cho mục đích tham khảo, phù hợp với vai trò hỗ trợ theo dõi dinh dưỡng hằng ngày. Tuy nhiên, người dùng không nên dựa hoàn toàn vào kết quả AI để đưa ra các quyết định dinh dưỡng quan trọng hoặc điều trị bệnh lý.

\subsubsection{Nhận xét về kiểm thử hiệu năng}

Mặc dù số liệu định lượng đang trong quá trình thu thập, nhóm có một số quan sát định tính về hiệu năng hệ thống:

\begin{itemize}
    \item \textbf{Thời gian quét AI chịu ảnh hưởng bởi nhiều yếu tố:} Khác với các thao tác đọc/ghi Firestore thuần túy (thường hoàn thành dưới một giây trong điều kiện mạng tốt), thời gian quét món ăn bằng AI phụ thuộc đáng kể vào ba yếu tố chính: (1) \textit{chất lượng kết nối mạng} giữa thiết bị và Cloud Functions, cũng như giữa Cloud Functions và Gemini API; (2) \textit{kích thước và độ phân giải ảnh} đầu vào — ảnh có dung lượng lớn cần thời gian truyền tải lâu hơn, mặc dù ứng dụng đã thực hiện resize trước khi gửi; (3) \textit{thời gian phản hồi của Gemini API} — model gemini-2.5-flash có tốc độ tốt nhưng thời gian phản hồi có thể dao động tùy theo độ phức tạp của ảnh và tải của dịch vụ tại thời điểm gọi. Trong quá trình kiểm thử thăm dò, thời gian quét AI thường dao động trong khoảng 3--8 giây cho một ảnh thông thường.

    \item \textbf{Các thao tác cục bộ và Firestore có phản hồi nhanh:} Các thao tác như khởi động ứng dụng, đăng nhập, tải nhật ký và lưu dữ liệu vào Firestore thường có thời gian phản hồi dưới 2 giây trong điều kiện mạng ổn định, nhờ cơ chế lưu đệm (offline persistence) của Firestore SDK và kiến trúc nhẹ của Flutter.

    \item \textbf{Cần đo đạc trên nhiều điều kiện thiết bị và mạng:} Để có bức tranh hiệu năng đầy đủ, cần thực hiện đo đạc trên ít nhất hai loại thiết bị (tầm trung và cao cấp) và trong hai điều kiện mạng (Wi-Fi và 4G). Các số liệu trong bảng trên sẽ được cập nhật sau khi hoàn thành các đợt đo tiếp theo.
\end{itemize}

\subsubsection{Nhận xét về kiểm thử bảo mật}

Kết quả kiểm thử cho thấy hệ thống đáp ứng các yêu cầu bảo mật cơ bản: dữ liệu người dùng được phân tách và bảo vệ theo UID thông qua Firestore Security Rules, khóa API Gemini không bị lộ ra phía client, và các thao tác quản trị được kiểm soát chặt chẽ qua cơ chế custom claim. Tuy nhiên, cần lưu ý một số hạn chế sau:

\begin{itemize}
    \item \textbf{Kiểm thử ở mức chức năng cơ bản:} Các test case trên chủ yếu xác minh cơ chế kiểm soát truy cập hoạt động đúng theo thiết kế. Đây là kiểm thử hộp trắng (white-box), dựa trên hiểu biết về cấu trúc hệ thống và Security Rules hiện có. Phạm vi kiểm thử chưa bao phủ các kịch bản tấn công phức tạp như leo thang đặc quyền qua thao tác token, khai thác race condition trong Security Rules, hay tấn công brute-force vào Firebase Authentication.

    \item \textbf{Chưa thực hiện penetration test chuyên sâu:} Hệ thống chưa trải qua đánh giá bảo mật độc lập từ bên thứ ba hoặc pentest toàn diện. Các rủi ro tiềm ẩn như lỗ hổng trong phiên bản Firebase SDK, cấu hình CORS trên Cloud Functions, hay tấn công từ chối dịch vụ (DoS) vào Cloud Functions chưa được kiểm tra một cách hệ thống. Đây là những nội dung cần được bổ sung trước khi đưa hệ thống vào vận hành production.

    \item \textbf{Khuyến nghị:} Trước khi triển khai rộng, nhóm đề xuất thực hiện kiểm thử bảo mật bổ sung bao gồm: rà soát toàn bộ Firestore Security Rules với công cụ mô phỏng (Rules Playground), kiểm thử fuzzing trên các Cloud Function, và thuê đơn vị độc lập thực hiện pentest. Ngoài ra, nên bật Firebase App Check để tăng cường bảo vệ chống lại request giả mạo từ bên ngoài ứng dụng.
\end{itemize}

\subsection{Kiểm thử tích hợp}

Kiểm thử tích hợp end-to-end giữa ứng dụng di động, Firebase và dịch vụ AI chưa được ghi nhận bằng biên bản chính thức. Báo cáo hiện chỉ mô tả kế hoạch kiểm thử, chưa kết luận trạng thái đạt hay không đạt cho nhóm kiểm thử này.

\subsection{Kiểm thử giao diện}

Kiểm thử giao diện trên nhiều kích thước màn hình và thiết bị khác nhau chưa được ghi nhận đầy đủ. Phần này cần được bổ sung sau khi có kết quả kiểm thử thực tế trên thiết bị hoặc trình giả lập.
